RC20 — Approved interface and upgrade

Functional version remains 0.9.0-1, build 20260902. The modern interface is enabled by default. Superusers select Modern or Classic under Admin → Global interface; the saved choice applies to all tenants and anonymous login. Lists, procedural blocks, menus and operations remain available. AlBot uses the configured provider with real session and tenant checks.

To upgrade Kubernetes, change the image and recreate the pod, retaining PostgreSQL, existing PVCs/mounts and Secrets. Application migrations run at startup: do not perform Full Import/bootstrap for a routine update or reset the admin password. Take a consistent database/file backup, start one new web replica/worker, verify migration and readiness, then restore scaling. Review startup probes and timeouts in older manifests.

If absent, Tenants Default is initialized from operational default configuration; rename any ordinary tenant using that reserved name beforehand. Review integration credentials copied into the shared source. The new UI does not require a new table. Do not change the PostgreSQL major version, PGDATA or PVC layout as part of the application-only update. Preserve SECRET_KEY and SETTING_ENCRYPTION_KEY. After schema migrations, rollback may require the matched backup as well as the previous image.

The required CI job generates real application screenshots and manuals with isolated demonstration data and installs them before image scanning. RC20 remains a source candidate; a production digest is recorded only after successful build, verification and scanning. Full procedure: docs/MIGRATION.md and docs/RELEASE.md in the package.

RC20 adds the independent cir_schema_migrations ledger and a migration phase before HTTP/HTTPS workers. Supported legacy schemas are adopted automatically; later startups execute missing revisions only. Unknown/newer histories, missing model columns and mandatory migration errors stop startup. Success markers share the final bootstrap transaction. Future releases must append a tested revision. Upgrades require maintenance without mixed application versions or concurrent restores; historical DDL may require an idempotent retry after failure.

RC18 — Tenants Default and cluster installation

The functional version remains 0.9.0-1. When absent, Tenants Default is initialized from the operational default configuration. Its catalogue, parameters, documents and templates are portable across instances; global Full Export and bootstrap include the shared source.
